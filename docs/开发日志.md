## 2026-07-15 · 方案 D 决策 + 四消费者 Demo

### 架构决策：方案 C（薄壳层）→ 方案 D（数据管道层）

**背景**：对 `main-ui`、`viewport-2d-kit`、`viewport-3d-kit` 进行了源码级分析。关键发现：
- `viewport-2d-kit` 是纯相机+交互工具包（`worldToScreen` / `zoomAtScreenPoint` / `constrainCamera`），**不画形状**
- `main-ui` 是工作台壳层（分屏/标签页/命令面板）
- `viewport-3d-kit` 提供 3D 场景（盒子/球体/圆柱体 + Three.js）但独立于 2d-kit

**结论**：采用方案 D——world-model-kit 前端只做数据管道：
- `@world-model-kit/core`：类型定义 + `WorldModelBridge` 接口
- `@world-model-kit/vue`：`useWorldModel` + `useAgentDiff` + `WorldModelProvider`
- 相机交给 viewport-2d-kit，形状交给消费者 Canvas，壳层交给 main-ui
- 每消费者 ~150 行集成代码，比维护通用组件（~2000 行）便宜

**设计文档更新**：
- 第九章：方案 C 废弃，改为方案 D + 新的架构分层图
- 第十四章：完全重写——消费者全链视图、需求矩阵、数据管道 API、四消费者参考实现
- 第十五章：决策表更新 + 新架构分层
