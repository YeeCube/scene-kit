## 项目概述

world-model-kit 是一个基于 RECS（SoA ECS 引擎）的**世界建模工具包**。它在 RECS 的向量化存储之上提供 NetLogo/Agents.jl 级别的 ABM 编程体验，同时保持多后端（NumPy/PyTorch/MLX/JAX）的性能优势。

### 关键设计原则

1. **工具包非引擎**：不接管用户主循环，控制权完全交还消费者
2. **三层接入**：L1 Raw → L2 API → L3 DSL，用户按需下沉
3. **SoA 优先**：所有数据以列式存储，操作全部向量化
4. **后端穿透**：计算后端完全委托 RECS，自身不引入后端依赖
5. **单一真相源**：设计文档（Obsidian）→ 本文档 → 代码，保持三者一致

## 架构概览

### 数据流

```
用户代码 (@step_for)
  ↓ 调用 L2 API
WorldModel
  ↓ 翻译为 RECS 操作
EntityPoolBridge
  ↓
RECS EntityPool (SoA) / Relation
  ↓
Backend (NumPy / PyTorch / MLX / JAX)
```

### 模块依赖图

```
world.py
  ├── entity_kind.py          (纯数据类)
  ├── entity_lifecycle.py     (依赖 entity_pool_bridge.py)
  ├── entity_pool_bridge.py   (依赖 RECS)
  ├── space/continuous.py     (依赖 entity_pool_bridge.py)
  ├── embedding/              (依赖 space/)
  ├── schedule/               (依赖 entity_lifecycle.py)
  ├── collect/                (依赖 world.py)
  ├── behaviors/              (依赖 world.py + space/)
  ├── events/                 (独立)
  ├── viewmodel/              (依赖 collect/)
  └── fields/                 (依赖 space/)
```

### 关键设计决策

| 决策 | 理由 |
|------|------|
| EntityKind 不持数据 | 数据在 RECS EntityPool 中，Kind 只是 dtype 模板 |
| 一 Kind 一 Pool | 不同 kind 的 SoA 列结构不同，分开存储最高效 |
| 嵌入关系用列存储 | 不用 Relation 表，直接做 `_emb_parent_id` 列，批量递归 O(N×D) |
| L3 全用 L2 实现 | L3 只是 L2 的 5-10 行组合，降低维护成本 |
| 自身不引入后端依赖 | 所有 `import torch/mlx/jax` 在 RECS 层，world-model-kit 只通过 `to_numpy()` 桥接 |

## 核心模块详解

### `entity_kind.py`

`EntityKind` 是 `@dataclass` 纯数据描述符。核心方法是 `_kind_to_dtypes()`，将布尔开关展开为 RECS 可消费的 `dict[str, np.dtype]`。

系统保留列（所有 kind 自动包含）：
- `_kind: U32` — kind 名称
- `_active: bool` — 激活标记
- `_step_fn: int32` — 注册的 step 函数 ID（-1 = 未注册）

### `world.py`

`WorldModel` 是用户唯一需要直接实例化的类。它持有一组 `EntityPoolBridge`（按 kind 索引）以及调度器、采集器、行为注册表。

核心方法分类：
- **注册**: `register_kind`, `unregister_kind`, `list_kinds`
- **生命周期**: `spawn`, `activate`, `deactivate`, `kill`
- **空间**: `move`, `move_to`, `distance`, `nearest`, `within_radius`, ...
- **调度**: `step`, `run`, `step_for`（装饰器）
- **采集**: `collect`, `aggregate`, `snapshot_every`, `add_metric`
- **导出**: `export_dataframe`, `export_viewmodel`, `export_networkx`
- **L1 直通**: `get_pool(kind)` → `EntityPool`

### `entity_lifecycle.py`

`EntityLifecycleManager` 管理一个 kind 下所有实体的状态转换。核心操作全部通过布尔掩码在 SoA 列上批量执行。

状态机：`PENDING → ACTIVE ↔ DORMANT → DEAD`

```python
# 关键属性（向量化）
active_mask = pool.d["_active"][:pool.size]           # bool 数组
active_indices = backend.nonzero(active_mask)[0]       # int 数组
```

### `entity_pool_bridge.py`

薄桥接层。将 `EntityKind` → `EntityPool` 的创建、属性读写、RECS 原语调用封装为 world-model-kit 风格的 API。

```python
bridge.create_pool(kind, capacity=1024) → EntityPool
bridge.get_pool("prey") → EntityPool
bridge.attr("prey", "x", indices) → np.ndarray
```

### `behaviors/`

每个行为是独立的纯函数模块：
- 输入：`(model, kind, **params)`
- 输出：无（直接修改 pool 列）
- 不创建新实体，不修改调度

### `events/`

`EventBus`：同步事件发布/订阅。所有事件在同一 tick 内触发。
`EventLedger`：可选的事件账本，支持确定性回放。

## 编码规范

### 通用规范

遵循 RECS 的编码规范：
- **风格**: PEP 8，类型注解优先（Python 3.10+ 语法）
- **文档注释**: Google 风格 docstring，中文说明
- **错误处理**: 公开 API 抛出明确异常（`ValueError`, `WorldModelError`）
- **日志**: 标准 `logging`，关键路径记录 DEBUG/INFO

### 命名约定

| 类型 | 约定 | 示例 |
|------|------|------|
| 模块 | `snake_case` | `entity_lifecycle.py` |
| 类 | `PascalCase` | `WorldModel`, `EntityKind` |
| 函数/方法 | `snake_case` | `register_kind()`, `move_along_curve()` |
| 私有成员 | `_prefix` | `_pools`, `_dtype_helper.py` |
| 常量 | `UPPER_SNAKE` | `DEFAULT_CAPACITY` |

### 类型注解要求

```python
# ✅ 正确
def spawn(self, kind: str, n: int = 1, **attrs: Any) -> np.ndarray: ...

# ❌ 错误
def spawn(self, kind, n=1, **attrs): ...
```

### 提交规范

```
feat: 新功能
fix: 修复
docs: 文档
test: 测试
refactor: 重构
chore: 构建/工具
```

## 测试策略

### 测试层级

| 层级 | 覆盖范围 | 工具 |
|------|----------|------|
| 单元测试 | 每个模块独立测试 | pytest |
| 集成测试 | 多模块协作 | pytest + demos/ |
| 烟雾测试 | 核心场景端到端 | demos/ 脚本 |
| 后端测试 | numpy/torch/mlx/jax 四后端 | pytest parametrize |

### 运行测试

```bash
# 全部测试
pytest

# 特定后端
pytest --backend=numpy
pytest --backend=torch

# 特定模块
pytest tests/test_entity_kind.py -v
```

### 测试编写要求

1. 每个公开方法至少一个正向测试
2. 边界条件（空数组、零容量、超大 n）
3. 错误路径（非法 kind、重复注册、未注册 step_for）
4. 多后端一致性（numpy vs torch 结果一致）
